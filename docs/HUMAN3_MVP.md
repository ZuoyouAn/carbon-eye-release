# 四维成长评估 MVP

本版本实现固定问卷与规则报告，入口 `/human3`。网站导航和项目页均有入口。

## 使用与数据

- 24 题：每象限 3 个行为题、1 个参照方式题、1 个阶段题，加上精力投入、领域联系、AI 使用和优先方向 4 题。
- 游客可以完成全部流程；上一题、修改回答和下载 Markdown 报告均可用。
- 不调用后端或大模型，不依赖生产数据库，Netlify 静态构建即可运行。
- 默认只在当前页面内存保留回答。用户主动勾选后才保存到本机 localStorage；刷新时校验版本和选项，重新计算报告。
- 清除按钮同时清除当前回答、报告及该问卷的本机存储，不影响网站其他数据。
- 后续大模型访谈尚未实现，页面明确显示开放状态，不提供虚假的可点击入口。

## 规则依据与局限

框架灵感来自 Dan Koe 的 HUMAN 3.0：
https://letters.thedankoe.com/p/prompt-human-30-self-discovery-and

中文题目、回答选项、阈值、模式匹配规则和报告模板是本项目的原创实现。不是原 skill 的标准计分表，也没有心理测量验证。

内部实现规则版本：`human3-questionnaire-v1`。内部值只帮助规则计算，不作为心理学等级，不出现在用户报告或导出中。

1. 三个行为题选项内部取 0–3；不确定为 null。至少两个有效行为回答才计算均值。
2. 均值小于 1.2 为“基础待建立”，1.2 到不足 2.2 为“正在形成”，2.2 及以上为“相对稳定”。此阈值是待校准的工程启发式。
3. 参照方式与阶段各自直接映射，不与实践平均值混合，不推断原框架的 Level 1/2/3。
4. 模式按以下顺序判断：任一领域信息不足 → 需要更多观察；投入超过八成且身体/关系基础弱 → 工作投入型；思维/关系稳定而身体/事业弱 → 探索寻路型；思维/身体稳定而关系/事业弱 → 自我优化型；全部基础弱 → 寻找锚点型；一个稳定领域且至少两个基础弱 → 单域专长型；全部稳定且报告相互支持 → 协同发展型；否则多向发展型。
5. 行为均值最低的领域作为候选重点；并列时只用用户的优先方向解开并列。没有明确偏好就保留多个候选，不指定唯一根因。信息不足时不得把 unknown 当成低值。
6. 反复尝试较多而持续实践较少时提示核实实践落差，不断言“假性成长”。AI 使用习惯只影响行动提示，不影响类型。
7. 各象限报告保留每道题的原始选项作为依据。无法通过本问卷推断的临床状态、物质使用风险和精确根因不作判断。

## 验证

在 `frontend` 目录运行：

```powershell
node --test src/features/human3/engine.test.js
npm.cmd run build
npm.cmd run dev -- --port 5175
```

测试覆盖六种原型、混合与信息不足、输入校验、未知项、并列重点、参照/阶段分离、实践落差、AI 提示及导出内容。

发布前以移动端与桌面验证：未选项不能继续；可以修改前面的回答；保存刷新后继续；完整回答刷新后重新查看报告；下载内容与页面一致；清除后刷新不恢复；其他网站路由仍可访问。

## 下一阶段

用真实用户反馈校准题目措辞与模式规则，变更规则时更新版本号。深度模式需要独立的后端会话 API、结构化模型输出及用户明确选择的数据上传。新增 API 应与本版纯浏览器评估分开，保持本版免费可用。
